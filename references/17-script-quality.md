# Script Quality Rules（脚本质量规则）

> 写任何 AA 脚本 / 注入代码前必读。原在 `SKILL.md` 内联，为控制入口体积下沉至此。
> 配套：`references/09-auto-assembler.md`（语法）、`references/10-aob-and-code-injection.md`（AOB）、
> `templates/`（可复制骨架）。

## 硬性要求

- **保留原始指令**，除非有意替换。被 hook 覆盖的指令必须在 newmem 中重放。
- **为注入代码分配足够内存**（`alloc`），不要写进未知的空闲区。
- **使用唯一标签与清晰符号**，避免与已有脚本冲突。
- **依赖 AOB 前先验证唯一性**（模块内唯一命中）。不唯一就加上下文字节，
  或改用「唯一锚点 + 偏移」访问第二个补丁点。
- **禁用时还原原始字节**，并 `unregistersymbol` / `dealloc`。
- **避免硬编码绝对地址**：存在稳定符号、指针或 AOB 时一律优先使用。
- **说明寄存器假设**：注入点用到的寄存器在该时刻确实指向什么，必须先验证再依赖。
- **x64 注意 RIP 相对寻址与寄存器位宽**，跳转目标必须落在指令边界上。
- **测试 enable→disable→enable，并重启目标程序**后再声称稳定。

## AOB 特征码：不得包含自身要覆盖的字节

这是一条独立且高频的坑，症状是「第一次能勾选，之后必须重启游戏才能再勾选」。

若特征码里包含了 hook 将要改写的那几个字节，补丁一旦打上，
该区域变成 `E9 xx xx xx xx 90`，`aobscanmodule` 就再也匹配不到自己的锚点，
`[ENABLE]` 首行即失败，CE 自动弹回勾选状态。

**规则**：hook 覆盖范围内的字节在特征码中一律写成 `??`，
让特征码只依赖覆盖区**之外**的上下文。这样脚本才是幂等的——
补丁在不在都能扫到，可以随时勾选 / 取消 / 重载。

详见 `examples/08-aob-injection.md`。

## 修改点选择

不存在「优先改运算」或「优先改 store」这样的固定优先级——
两者都可能有下游消费者。正确顺序是：

1. 先用观察型 hook 搞清这段代码**服务几个对象**（`SKILL.md` 原则 6）。
2. 再看被改的值**除写回之外还有没有别的消费者**
   （是否被传入后续 `call`、是否参与索引计算、是否影响分支）。
3. 两者都确认后，选副作用最小的点下手；不确定时优先 hook**调用点**而非被调用函数。

## 交付前检查清单

- [ ] AOB 在模块内唯一，且不含被覆盖字节
- [ ] 原指令已重放，跳回地址在指令边界
- [ ] `[DISABLE]` 能完整还原（含 `unregistersymbol` / `dealloc`）
- [ ] enable→disable→enable 通过
- [ ] 重启目标程序后重新勾选通过
- [ ] 非目标对象（敌人 / NPC）行为未受影响
- [ ] 若曾用外部工具直接写内存，交付前已还原原始字节
      （否则用户加载 CT 时 AOB 扫不到）
