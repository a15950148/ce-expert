# Shared Code and Object Filtering（共享代码与对象过滤）

同一条指令可能同时处理玩家、敌人、NPC、子弹等所有对象——这是「改了数值连敌人也变」的根因。要在共享代码里只影响目标对象，必须在运行时判断「当前这条指令在处理谁」。

## 方法
1. 捕获每种对象类型命中该指令时的寄存器上下文（在「Find out what writes/accesses」窗口多次触发，分别记录玩家/敌人命中时的寄存器）。
2. 对比这些对象的内存，找它们在某偏移上的稳定差异（对象指针本身、ID、team、type、或玩家专属基址）。
3. 选一个**稳定判别量**：对象指针、对象 ID、队伍、类型，或已知的玩家基址。
4. 在注入逻辑里**只对目标对象分支**：满足条件才执行自定义逻辑。
5. 对所有其他对象**执行原始行为**，保证游戏逻辑不被破坏。

## 判别量优先级
- 玩家专属基址（最稳，但只适用「只改玩家」）→ 直接比较 this 指针是否等于玩家基址。
- 对象 ID / team / type 字段（通用，适合「只改某队/某类」）→ 从对象指针 + 偏移读出字段比较。
- 当前武器 / 当前弹药对象（只改当前武器）→ 比较武器对象指针。

## 关键警告
- 不要因为在某一次断点命中时某寄存器指向玩家，就假设它**总是**指向玩家。必须在多次、多对象命中下验证。
- 寄存器在指令执行到不同阶段含义会变；在注入点读取判别字段时，确认该偏移在此时刻确实有效。
- 分支逻辑要放在原指令之后、跳回之前，且只改变目标对象的状态。
