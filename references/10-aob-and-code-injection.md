# AOB and Code Injection（AOB 与代码注入）

AOB（Array of Bytes）用指令字节而非固定地址来定位代码，因此能跨越重启与地址随机化，是稳定方案的核心。

## 什么是 AOB
AOB 是一串十六进制字节，例如 `48 89 5C 24 08 55 56 57 48 83 EC 20`。CE 用它在模块里搜索唯一匹配，得到符号（如 `inj`），后续脚本引用该符号而非绝对地址。

## 工作流
1. 用「Find out what writes/accesses」找到相关指令（见 references/07）。
2. 查看该指令及其前后若干字节，确认属于某个模块（如 game.exe）。
3. 生成足够具体的 AOB：太长易失配，太短易多匹配。
4. 验证解析唯一（CE 应只返回一个结果；多个结果说明特征不够独特）。
5. 分配 code cave（`alloc`）。
6. 在其中执行自定义逻辑。
7. 按需补跑被位移掉的原指令。
8. 跳回原流程。
9. 禁用时还原字节。

## 构造 AOB 的技巧
- 优先纳入**操作码 + 立即数 + 模块内相对偏移**等稳定部分。
- 用 `??` 通配易变字节（如寄存器编码随上下文变化处）。
- 避开包含绝对地址（如直接 `mov rax, 0x140000000`）的字节，它们随 ASLR 变化，应通配或避开。
- 目标更新后务必重新验证唯一性。

## 应避免
- 完全由易变地址或重定位敏感字节组成的模式。
- 假设地址固定而硬编码——一旦目标重启即失效。
- 目标更新后不重新校验。
