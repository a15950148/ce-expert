# Memory and Process Model（内存与进程模型）

## Concepts（概念）
- **Process（进程）**：运行中的程序，拥有独立的虚拟地址空间。各进程的内存互不干扰。
- **Module（模块）**：被映射进进程的可执行文件或动态库（如 `game.exe`、`UnityPlayer.dll`）。
- **Base address（模块基址）**：模块加载到内存的起始地址，每次启动可能不同。
- **Module-relative offset（模块内偏移）**：从模块基址算起的固定偏移；加基址得到运行时地址。
- **Static address（静态地址）**：形如 `"game.exe"+0x1234`，随模块基址自动重定位。
- **Dynamic address（动态地址）**：由运行时分配产生，重启后通常变化。
- **Pointer（指针）**：某块内存中存放的值，被解释为另一块地址。多级指针 = 指针指向的仍是地址。

## Address resolution（地址解析）
```
运行时地址 = 模块基址 + 模块内偏移
指针链解析：base → [base+off1] → [..+off2] → ... → 最终值
```
- 用 CE 指针扫描可自动求出多级偏移链。
- 模块基址变化不影响偏移，所以"模块+偏移"和指针是重启稳定的两种主要手段。

## Analysis rule（分析原则）
- 不要因为地址会变，就默认"只能做指针扫描"。
- 代码访问（find what accesses/writes）常能揭示稳定的对象路径或注入点（见 `workflows/06`、`07`）。
- 64 位下注意 RIP 相对寻址与寄存器位宽（见 `references/08-x86-x64-assembly.md`）。
- 优先用符号、`"模块"+偏移`、AOB 或指针，避免硬编码绝对地址。

## When to use which（选型）
| 现象 | 首选路径 |
|------|----------|
| 地址重启不变 | 直接静态地址 / 模块+偏移 |
| 地址重启变化但指针稳定 | 指针扫描（多级偏移） |
| 同一代码服务多对象 | 代码注入 + 对象过滤（workflows/11） |
| 值由服务器下发 | 本地修改无效，见 references/15 |
