# Pointer Analysis（指针分析）

指针链从一个稳定的基址出发，经由一级或多级偏移，最终解析到目标地址。

```
基址 (module + 固定偏移, 如 game.exe+0x1234)
  └─> 偏移 [0x10] → 中间节点地址
        └─> 偏移 [0x2C] → 目标值地址
```

## 关键概念
- **基址 (Base)**：通常是模块（.exe/.dll）加载地址加固定偏移。进程重启后偏移不变，只有模块基址随 ASLR 变化，CE 会自动重定位。
- **偏移 (Offset)**：每一级结构成员之间的字节差，是编译期常量，通常不随版本变。
- **层数 (Level)**：偏移的级数。层数越多越脆弱，跨版本或不同场景更易失效。

## 工作流
1. 找到已验证的目标地址（值正确、可复现变化）。
2. 确认它是否能在重启后存活（通常不能，这正是做指针的原因）。
3. 运行指针扫描，或回溯代码定位基址（见 `workflows/04-pointer-scan.md`）。
4. 重启后重新获取目标地址。
5. 用新地址重新扫描/过滤，找到在两次重启中都成立的指针。
6. 在多次重启与相关游戏状态间验证。

## 注意事项
- 一次能用的指针不一定稳定。深层指针在更新或不同场景（如不同地图）下可能失效。
- 优先选择**层数少、基址来自模块、重启多次仍唯一**的指针。
- 没有合适指针时，改用代码访问方式（`workflows/06-find-accessing-code.md` / `workflows/07-find-writing-code.md`）更稳定。
- 若指针在重启后失效，见 `diagnostics/04-pointer-does-not-work.md`。
