# Identify Player Object（识别玩家对象）

## Goal
在内存中稳定地识别出「玩家」这个对象（其基址或判别字段），作为后续「只改玩家」逻辑的依据。成功条件：得到一个在重启/场景切换后仍指向玩家、且不与敌人/NPC 混淆的标识。

## Prerequisites
- 已能读到玩家某个数值地址（来自 `workflows/01`/`02`），并回溯到对象基址（见 `workflows/08`）。
- 已读 `references/06-memory-structure.md` 与 `references/11-shared-code-and-object-filtering.md`。

## Procedure
1. 找到玩家血量/坐标等值的写入指令，记录其 `this` 指针（如 `rax`）→ 这是玩家对象基址候选。
2. 把该基址加入地址列表，冻结它，重启目标后确认它是否重新指向玩家（动态堆地址通常不行，需指针化）。
3. 在该基址上用 Grouped view 查看玩家专属字段：
   - 是否有「是否玩家」标志位（flags & 0x1）。
   - 是否有固定的对象 ID（玩家 ID 通常是某常量或唯一范围）。
   - 是否有 team 字段且玩家固定为某值。
4. 在玩家与其他对象（敌人/NPC）间对比这些字段，确认哪个是**玩家独有且稳定**的判别量。
5. 优先方案：用「玩家基址相等」或「判别字段匹配」作为注入分支条件（见 `workflows/11`）。

## Decision Branches
- 玩家没有显式标志位：改用对象 ID 落在玩家区间、或玩家基址由某稳定指针解析得出。
- 玩家基址每次重启都变：不要直接比较地址，改为比较「由稳定指针解析出的玩家对象」或判别字段。
- 多玩家/联机场景：本流程面向单机本地玩家，联机对象的判别需额外信息。

## Verification
- 判别量在多次重启、进出不同场景后仍能唯一识别玩家。
- 记录：判别方式（基址/ID/team/flag）、对应偏移、验证的重启次数。
