# Handle Shared Code（处理共享代码）

## Goal
在同一条被玩家、敌人、NPC 等所有对象共用的指令上做注入，使自定义逻辑**只作用于目标对象**，其他对象保持原行为。成功条件：目标对象按预期被修改，非目标对象完全不受影响，且游戏逻辑正常运行。

## Prerequisites
- 已用 `workflows/07` 找到写入/访问指令，并确认多个对象都命中它。
- 已用 `workflows/09`/`10` 还原结构并识别出玩家/目标对象的判别字段或基址。
- 已读 `references/11-shared-code-and-object-filtering.md` 与 `references/09-auto-assembler.md`。

## Procedure
1. 用 AOB 定位该共享指令（`workflows/12-create-aob-injection.md`），生成注入骨架。
2. 在 `[ENABLE]` 的 `code:` 段，先**重放被覆盖的原指令**，确保原行为不被破坏。
3. 在重放之后、跳回之前，插入判别逻辑：
   - 读取当前对象指针（如 `rax` 指向的对象基址）。
   - 比较判别量：基址相等 / ID 匹配 / team 匹配 / flag 置位。
   - 成立 → 执行自定义逻辑（如强制写值、跳过扣减、放大数值）。
   - 不成立 → 不执行，直接跳回。
4. 在 `[DISABLE]` 段还原原始字节。
5. 测试：启用后让玩家与目标对象、敌人分别触发该指令，验证仅目标受影响。

## 判别写法要点
- 读取判别字段：`mov eax,[对象基址+偏移]`，再与常量比较（`cmp`/`test`）。
- 指针相等：`cmp rax, playerBase` 或比较从稳定指针解析出的值。
- 注意寄存器生命周期：注入点使用的寄存器必须在该时刻确实指向目标对象（先多次验证）。

## Decision Branches
- 判别后误伤了其他对象：判别量选错或偏移不对，回到 `workflows/09`/`10` 重新确认区分字段。
- 注入导致原行为缺失（如敌人也卡住）：原指令未正确重放，检查覆盖边界（`diagnostics/07`）。
- 重启后判别失效：判别量用了动态地址，改用稳定字段或指针（`workflows/03`/`04`）。

## Verification
- 玩家受伤不掉血/敌人正常受伤、或仅目标伤害被放大——且反复触发与重启后行为一致。
- 记录：AOB、判别字段与偏移、自定义逻辑、原指令重放、DISABLE 还原字节。
